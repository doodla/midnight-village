# Contract test machinery

Tests may only claim states the server can produce. The payloads come from `contract_samples/` at the repo root, recorded from the real server (`just samples` in `backend/` regenerates them; the backend suite fails while they are stale; how they are recorded: `backend/tests/README.md`). This folder:

- `contract_samples.dart` loads them (`dart:io`, found from the working directory upwards; `ContractSamples.map(name)`, `bodyFor(method, path, status:)`).
- `server_json.dart` builds payloads FROM a sample, changing values only (a key the sample lacks throws): `serverPrompt(kind)`, `serverNightResult(kind, info:)`, `serverPlayerList`, `serverResults`, `serverLobby`, `serverLogEntry`, `serverMyTable`, `serverRecentGames`, `serverOnlineStats`; players lists carry each seat's own token and seat number (`seatFields`). `GameMeJsonBuilder` (`/me/` per phase; TitleCase roles only; window 1 only with a Doppelganger in the deck) and `GameEvents` (no `phase_change` to the night, no `connected` in `/me/` players) work the same way. `GameTestSetup` registers `/me/`, the player list (presence, `away:`), and the server's own bodies for action/vote/end-discussion and `registerPost` defaults.
- `contract_shape.dart` is the guard: every body registered on `MockHttpClient` (hook installed by `test/flutter_test_config.dart`) and every event pushed with `MockWebSocketChannel.addServerEvent` must match the samples of that endpoint+status / event type: no key path the server never sends, no other JSON type, no always-sent key missing (dictionary keys such as role names and player ids are wildcards). Variants, not a union: first the night protocol (`nightProtocolOf` in `contract_samples.dart`, the one helper: `index.json` does not record it, so a `/me/` with a `stage` key is protocol 2, the events `night_window` and `progress` are protocol 2, the rest is shared), a payload being compared only with samples of its own protocol and refused when none exist; then only the samples of the payload's own situation count (the `phase` of a `/me/` or `phase_change`, a prompt's `role_acting_as`, a night result's kind, for each `night_results` entry too), so a night-only key in a discussion `/me/` is refused; when no sample has that situation, all samples of the endpoint count. An error body needs a sample of that endpoint answering that status (record one in `backend/tests/contract/scenarios.py`). It does not check values. A test about malformed input says so: `thenReturn(..., offContract: true)`, `registerGet(..., offContract: true)`, `addOffContractEvent`. 5xx bodies are not checked.
- Strict mocks: a request with no registered response fails the test (reported to the test zone even if the app swallows the error); an error status is answered as a failed request with its body; registered bodies are deep-copied. `MockWebSocketChannel.send` fails (the server takes no client messages) unless made with `acceptsSends: true` (socket plumbing tests only).
- Domain objects in a test (`GameSessionState`, `LobbyState`, prompts, results, `HostChange`, `VoteRevealData`) come from `FromSample` (`from_sample.dart`): a checked payload parsed exactly as the app parses it, then client-only state set with `copyWith`. Never a constructor with made-up values.
- `ws_sequence/*` samples are not events: each is, per seat, the list of event types it heard. The guard validates them as that (every type has a `ws` sample), `checkSocketEvent` never takes one. `game_models_test.dart` parses every recorded `/me/`, each by its protocol (protocol 1 `GameSessionState`, protocol 2 `GameMe`). `FromSample.gameMe`, `.myTable`, `.progress` and `.event` give the protocol-2 objects; `test/helpers/contract/sample_sets.dart` lists every protocol-2 `/me/` and every lobby body; `test/helpers/protocol_two_setup.dart` wires the protocol-2 game to the strict mocks (its clock starts before every recorded deadline).
- `fixture_sources_test.dart` scans `test/` and `test_screens/` and fails on any way around the guard: a mocked HTTP client (`AuthenticatedClient`, `ApiClient`, `Dio`), a mock answering with a literal map, a server-backed domain constructor, a literal map passed to `fromJson`. Its allowed list: the debug controller test's mocked `DebugApiClient` (every answer goes through `checkHttpBody`), the debug client test's `_ServerAdapter` (same), and the design system's `User` example. It cannot see a literal map stored in a variable and parsed later.
- The app parses strictly: what the samples show the server always sends is required (a missing key throws), so a fixture cannot lean on a default; where the server really omits a value (`settings.roles` on a new table, `current_role` before the results, `has_voted` outside the vote, a null `deadline`) a test built on that sample says so.
- The web integration test cannot read files: its mock bodies are in `integration_test/helpers/server_bodies.dart`, checked against the samples by `contract_guard_test.dart`.
