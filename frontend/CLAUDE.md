# Frontend — Midnight Village

## Commands

```bash
just run               # Run on web (Chrome, port 3000)
just test              # Run tests
just analyze           # Dart static analysis (tool/analyze_gate.sh: fails on any issue but tracked old-look uses)
just gen               # Riverpod code generation (run after changing providers)
just watch             # Code generation in watch mode
just test-integration  # Integration tests on Chrome
just screens           # Render every screen and the component sheet next to the mocks (see below)
just skin-art          # Regenerate assets/skins/shadow_paper/ from docs/design/art/ (needs uv)
just playtest-pack     # The cold-read pack: four first-game journeys to build/playtest/
```

## Code Generation

Riverpod uses code generation. After modifying any provider or adding `@riverpod` annotations, run `just gen` to regenerate `*.g.dart` files. Forgetting this causes analyzer errors on generated code that look like real bugs.

## Debug & Integration Harness

- `just test-harness` runs the deterministic e2e harness in `test_e2e/` and boots (and stops) the harness backend on `:8001` itself. The API runner replays all 29 reference games from `backend/tests/onuw/data/reference_games.json` through the two-window night and asserts the debug-state oracle; the UI runner plays a subset through the real widget tree with a live WebSocket and writes per-player PNG filmstrips. `api_lifecycle_test.dart` (helpers `harness/live_table.dart`, `PlayerWire.connectLobby`) runs the table lifecycle through real sockets: play again, dropped phones (night and vote grace, `night_results`) and host handover; the oracle's `pending_timers` shows which timers are armed. Rules for harness tests: `DebugTableController.driveAs` is strict (a refusal throws; `lenient: true` is for the toolbar), wall-clock checks use `TimeBox`, waits take explicit timeouts, and nothing is slept on. It is intentionally NOT under `test/` and NOT part of `just test`. Full docs: `docs/dev/debug-harness/`.
- The night is two windows: a player may get a prompt, submit, then wait with no result until the window closes (`submitAction` shows waiting); results arrive together and are held until dismissed; the Doppelganger's look result arrives with her follow-up prompt in the same window. Under night protocol 1 (the old screens) `skip` is the "do nothing" control wherever the server's prompt lists it; under protocol 2 (the rebuilt night) every phone sends one `choose` per window with the stage, and doing nothing is picking "You" alone, on every prompt.
- Shared test helper `MockHttpClient` lives in `integration_test/helpers/` (the web integration build cannot import out of its root); `test/helpers/mock_http_client.dart` re-exports it.
- `/debug` route (dev-only, gated by const `Env.isDev` so it tree-shakes out of prod) — the debug toolbar: spin up a table, switch player perspectives, god panel, auto-drive. Core lives in `lib/core/debug/`.

## Server payloads in tests (contract samples)

Tests may only claim states the server can produce. The payloads come from `contract_samples/` at the repo root, recorded from the real server (`just samples` in `backend/` regenerates them; the backend suite fails while they are stale). `test/helpers/contract/`:
- `contract_samples.dart` loads them (`dart:io`, found from the working directory upwards; `ContractSamples.map(name)`, `bodyFor(method, path, status:)`).
- `server_json.dart` builds payloads FROM a sample, changing values only (a key the sample lacks throws): `serverPrompt(kind)`, `serverNightResult(kind, info:)`, `serverPlayerList`, `serverResults`, `serverLobby`, `serverLogEntry`, `serverMyTable`, `serverRecentGames`, `serverOnlineStats`; players lists carry each seat's own token and seat number (`seatFields`). `GameMeJsonBuilder` (`/me/` per phase; TitleCase roles only; window 1 only with a Doppelganger in the deck) and `GameEvents` (no `phase_change` to the night, no `connected` in `/me/` players) work the same way. `GameTestSetup` registers `/me/`, the player list (presence, `away:`), and the server's own bodies for action/vote/end-discussion and `registerPost` defaults.
- `contract_shape.dart` is the guard: every body registered on `MockHttpClient` (hook installed by `test/flutter_test_config.dart`) and every event pushed with `MockWebSocketChannel.addServerEvent` must match the samples of that endpoint+status / event type: no key path the server never sends, no other JSON type, no always-sent key missing (dictionary keys such as role names and player ids are wildcards). Variants, not a union: first the night protocol (`nightProtocolOf` in `contract_samples.dart`, the one helper: `index.json` does not record it, so a `/me/` with a `stage` key is protocol 2, the events `night_window` and `progress` are protocol 2, the rest is shared), a payload being compared only with samples of its own protocol and refused when none exist; then only the samples of the payload's own situation count (the `phase` of a `/me/` or `phase_change`, a prompt's `role_acting_as`, a night result's kind, for each `night_results` entry too), so a night-only key in a discussion `/me/` is refused; when no sample has that situation, all samples of the endpoint count. An error body needs a sample of that endpoint answering that status (record one in `backend/tests/contract/scenarios.py`). It does not check values. A test about malformed input says so: `thenReturn(..., offContract: true)`, `registerGet(..., offContract: true)`, `addOffContractEvent`. 5xx bodies are not checked.
- Strict mocks: a request with no registered response fails the test (reported to the test zone even if the app swallows the error); an error status is answered as a failed request with its body; registered bodies are deep-copied. `MockWebSocketChannel.send` fails (the server takes no client messages) unless made with `acceptsSends: true` (socket plumbing tests only).
- Domain objects in a test (`GameSessionState`, `LobbyState`, prompts, results, `HostChange`, `VoteRevealData`) come from `FromSample` (`from_sample.dart`): a checked payload parsed exactly as the app parses it, then client-only state set with `copyWith`. Never a constructor with made-up values.
- `ws_sequence/*` samples are not events: each is, per seat, the list of event types it heard. The guard validates them as that (every type has a `ws` sample), `checkSocketEvent` never takes one. The app parses only protocol-1 `/me/`; `game_models_test.dart` lists the protocol-2 ones as not parsed yet, to be moved into the parsing test when the app speaks protocol 2.
- `fixture_sources_test.dart` scans `test/` and `test_screens/` and fails on any way around the guard: a mocked HTTP client (`AuthenticatedClient`, `ApiClient`, `Dio`), a mock answering with a literal map, a server-backed domain constructor, a literal map passed to `fromJson`. Its allowed list: the debug controller test's mocked `DebugApiClient` (every answer goes through `checkHttpBody`), the debug client test's `_ServerAdapter` (same), and the design system's `User` example. It cannot see a literal map stored in a variable and parsed later.
- The app parses strictly: what the samples show the server always sends is required (a missing key throws), so a fixture cannot lean on a default; where the server really omits a value (`settings.roles` on a new table, `current_role` before the results, `has_voted` outside the vote, a null `deadline`) a test built on that sample says so.
- The web integration test cannot read files: its mock bodies are in `integration_test/helpers/server_bodies.dart`, checked against the samples by `contract_guard_test.dart`.

## First-time play

The rebuilt screens follow `docs/specs/frontend/first-time-play.md` (teach once, say little); its sections 7 and 8 override the text above them. The shared pieces take plain data and callbacks and never touch the network:

- **Words**: every string a player sees is in `lib/design_system/copy/copy.dart` (`Template` for gaps); none in widgets. `test/design_system/copy/copy_budget_test.dart` holds them to section 1 mechanically: the banned list, sentence, headline, button, banner and spoken lengths, the one question, no gesture explained (`gestureKept` lists the one line the spec keeps), and every screen state's word budget (`screen_states.dart`). `bad_copy_fixture.dart` proves each rule fails. A new screen state is a new entry there. `widget_strings_test.dart` reads the syntax of `lib/design_system/{primitives,faces,night,teach}` and fails on any string there that could reach a screen or a screen reader (the server's snake_case keys, letterless joins and developer-only messages aside).
- **Role text**: `RoleText.of(role)` (`copy/role_text.dart`), the one table for the 04 face, the role sheet (`RoleSheetBody`) and the team tags.
- **Cues**: `LearnedCues` (`teach/learned_store.dart`) keeps `mv.learned.v1.<id>` in `DevicePreferences`, read before the first frame (`restoreLearned()` in `main`). Ids: `hold` (any reveal), `hold_you` ("You" on the night board), `hold_my_night` (08), `night_choose`, `vote_lock`. The debug toolbar's "Reset learned cues" calls `ref.read(learnedCuesProvider.notifier).reset()`. `TeachOnce` shows a cue until learned, or for 3 s after its `CueReplay` fires (a tap on a locked gate); `TeachingHold` is a `HoldToReveal` with the thumbprint cue (`HoldCue`); `CueWave` is the board's lift and the vote rows' nudge. Reduce motion makes them still.
- **Gates**: only 04's "Ready" (a 0.8 s reveal) and a button waiting for a valid pick ("Choose a card", "Choose 1 more"); `PrimaryButton.locked` replays the screen's cue. "Ready to vote" is never locked. Nothing adds a wait or assumes a timer length: lengths come from the server.
- **Secrets**: `HoldToReveal` shows its face 120 ms after the press for as long as it is held (no cap) and counts a reveal at 0.8 s; a tap is never a reveal (it reaches the cover at once: on the board, a pick); a screen reader, switch or keyboard shows it until activated again; it hides on focus loss, a covering route and the app leaving the foreground. The face is a `HeldFace` above the touch point (below it, clear of the thumb, when there is no room above), never under the thumb: one size, the whole role card with its portrait in colour, text scale capped at 1.6, words out of semantics unless activated. Its content is read from `/me/` by `NightReport.fromMe` (`faces/night_report.dart`): `card` (04), `you(prompt)` ("You" at night; the Doppelganger's copy during her follow-up), `myNight` (08: the result first, window 1's page when the deck holds the Doppelganger, then "Dealt"; the same count on every phone). The results (`NightResult.fromEntry`, `WindowOneResult.fromEntries`) and prompt kinds (`NightPrompt.fromKind`) are parsed from the server's words, one to one.
- **The night board**: `NightBoard` (`night/`) takes the seats (`NightSeat.seatsOf(me)`), this phone's id, its `ChoosePrompt.fromMe(me)` (the stage, the window, the kind, and `PickRule.fromPrompt`: the prompt's `shapes` (`{"players": n}`, `{"center": n}`, `{"any": 1}`) over its `valid_targets`; "You" alone, doing nothing, is always a choice), the face of "You", the seconds left, and `onChoose(stage, picks)`, which answers a `ChooseAnswer` (`fromStatus`: `200` taken; `409 wrong_stage`, `409 already_chosen` or any refusal stale, so the caller refetches `/me/`; no answer `notSent`, the only case that shows `Notice` "Not sent." with "Try again"). A card the prompt cannot take does not select; Choose shows "Chosen" at once and never waits; one Choose per turn, and the board re-arms only on a new stage or turn (`ChoosePrompt.turn`: 1 only for the Doppelganger's follow-up, so `max_chooses` never gives another phone a second). Four cards to a row for six seats or fewer, five beyond, four with large text; a body that runs past the button fades at its lower edge. Tests build every night input from the recorded protocol-2 samples (`recordedMe`, `Viewer` in `test/helpers/sheet/sheet_data.dart`), never by hand: the results, seats, rule and prompt have no public constructor, and `night_fixture_sources_test.dart` catches the rest. `night_layout_test.dart` holds the board's layout and motion to be the same on every phone of a recorded game and what the table sees after Choose to be the same whatever the answer; `night_board_test.dart` and `pick_rule_test.dart` cover the rest.
- **The look**: one amber fill per screen (`amber_rule_test.dart`), the reading floor (16 px to act, 14 px captions; `just screens ... strict` fails a player screen below it), plain pips, no uppercase micro-labels.
- **Pictures**: the component sheet's screen pages are these pieces in each state (`component_sheet_states_test.dart` checks each page reaches its state); a page is a phone of a recorded game (`ComponentPage.viewer`). `just playtest-pack` writes the cold-read pack: the host, guest, sleeper and Seer journeys through recorded game 7, each phone's own taps and faces, with what it has learned carried from screen to screen (`ComponentPage.teaches`), as `build/playtest/<journey>/screen-NN.png` (`test_screens/playtest_pack_test.dart`).

## The skin: one look, values from the skin

There is one look today: **Shadow paper** (from `docs/design/mocks/S*.dc.html`). A future look is a separate design with its own layouts, components and original art, not a recolouring of these screens. The values still come from the skin, so nothing is hard-coded: the look lives in a `Skin` (`lib/design_system/skin/`) holding per-ground colour roles and hard offset shadows (`Ground`: night, day, and the paper inside a card), type roles (`SkinType`), shape (`SkinShape`), tilt roles (`SkinTilt`, picked with `Tilt.card`, `Tilt.scatter(i)`, ...), the scrim, the dimmed opacity and the art set. Spacing and motion are not in it: `Space` and `Motion` in `lib/design_system/layout/space.dart`, read as `Space.md` with no skin in reach. The registry is `SkinId` (`skin_id.dart`), with the one entry `shadowPaper`.

- Build screens from the primitives in `lib/design_system/primitives/` and read values through `context.skin`, `context.ground` and `Space`/`Motion`, never literals. `docs/design/mock-to-skin.md` maps every element of every mock to the primitive and role that draws it; `test/helpers/component_sheet.dart` rebuilds each mock that way (the pages `join` to `results`), so copy from there. Primitives: `ScreenFrame` (with `topArt` + `TopArtLayout`, or a full-bleed `topSlot`), `Band`, `TimerBand.sun`/`.bar`, `WorldTimer.candle`/`.candleCompact`, `PrimaryButton` (`.locked`, `.quiet`, `.done`)/`SecondaryButton`(`.paper`) at a `ButtonSize`, `SkinField.paper`/`.code`, `PaperCard`, `Pill`, `PresetChip`, `StatusDot`, `TagChip`, `CountBadge`, `OutlinePanel`, `Notice`, `PaceTile`, `PeekBox`, `PlayerToken` (a `TokenSize`), `PlayerRow` (a `PlayerRowSize`, with `Tally`), `RoleCard` (thumbnails and grid), `RoleSheetBody`, `RolePortrait`, `FaceDownCard` (a `FaceDownSize`), `ProgressPips`, `HoldToReveal`, `SheetScaffold`/`showSkinSheet`/`showSkinDialog`, `FitLine` (one line, set smaller), `FitWords` (wraps between words, never inside one; the buttons, labels, chips and captions use it), `ArtPicture`. Fixed sizes are maximums: thumbnails, face-down cards and the candle shrink to their parent.
- Grounds are always declared: the app root declares night (`App`), `ScreenFrame`, `PaperCard`, the bands and `PeekBox` declare theirs, and `GroundScope` is an `InheritedTheme`, so sheets and dialogs carry the ground they were opened on. `GroundScope.of` asserts when there is none (tests: `pumpSkinned`).
- Type: the brief's scale (design brief section 4) with one named hero role per screen (`heroTitle`, `heroCode`, `heroVerdict`, `heroWinner`); `skin_contract_test.dart` holds the skin to it and every new role must be given a kind there.
- Amber is the one warm accent: one amber fill per screen, the primary action (`ground.accent`), edged in ink by day (`ground.accentEdge`). A selection is lift plus an outline (`ground.selection`), never amber or a fill. `amber_rule_test.dart` counts the amber fills on every component-sheet page.
- Layout code never asks which skin is active: no `SkinId`, no skin comparisons outside `skin/skins/`, the registry, the app theme and `main` (`skin_identity_test.dart` scans `lib/` for every registry name).
- The Material theme comes from the skin (`skinTheme`, `appThemeProvider`, always `SkinId.fallback`); `Skin.lerp` never blends. There is no skin switch and no saved skin. The debug toolbar's "Reset learned cues" forgets what this device has been taught.
- Fonts: Gloock and Figtree, under `fonts:` in pubspec.yaml (the engine loads them at start); only the weights the type roles use ship. Their OFL licences are registered for the licences page in `lib/main.dart`.
- Art: `assets/skins/shadow_paper/{roles,tokens,scenes}/*.webp`, at the pixel sizes the `ArtSet` declares (the contract test decodes each to check). Every picture is drawn through `ArtPicture`, which decodes it at the size it is shown (`ArtImage.decodedFor`: the full size, a half or a quarter). At start `SkinLoader.prepare` runs `precacheArt(secretArt(skin))`, decoding every role portrait and the card back at the sizes secrets show them, so the first hold is never empty and a reveal fetches nothing (a role-specific fetch at reveal time would be a side channel on shared Wi-Fi; `art_test.dart` checks). All ten tokens are drawn; a token id this app does not know (`TokenId.fromServer` gives null) is a plain disc.
- Regenerating the art: `just skin-art` (`uv run --with pillow python tool/skin_art.py`) resizes the originals in `docs/design/art/`. Deterministic: run it twice and nothing changes.
- Tests on the skin: `skin_contract_test.dart` (scale, faces, art sizes, shapes, the accent and selection rules), `amber_rule_test.dart`, `contrast_test.dart` (WCAG AA measured on the painted pixels of every component-sheet page on every ground: text against the colour actually behind it, with the opacity above it; disabled controls exempt, busy ones not), `fit_sweep_test.dart` (every page at 320/360/390 wide and text x1/1.3/2: no overflow and no word broken across two lines), the goldens.

## Fonts in tests

`test/flutter_test_config.dart` loads every family in the build's FontManifest (Gloock, Figtree and MaterialIcons) via `test/helpers/test_fonts.dart`, so widget tests, goldens and the screen gallery draw real glyphs for those. Families the app names but does not bundle are drawn in Figtree stand-ins: `Roboto` (Material's default, used by the test theme) and the old look's google_fonts families (until the old look is removed). Build old-theme styles in a unit test through `quietRetiredFonts` to keep google_fonts' load errors for those families out of the output. Delete the retired section of `test_fonts.dart` with the old look.

## Goldens

One baseline set, in `test/design_system/goldens/`, made on Linux. Golden-tagged tests are skipped on other OSes (`dart_test.yaml`): font rasterisation differs per OS, and CI (Linux) is the source of truth. Regenerate with `just flutter-golden-update` on Linux, or from the CI workflow (see `.github/workflows/flutter-tests.yml`). Failure diffs go to `test/design_system/failures/` (gitignored).

## Screen gallery

`just screens [width] [report|strict]` (also from the root) renders every screen in the catalogue from the real widgets, in the app's theme, with images precached, to `build/screens/<id>.png` at 390x844 (2x), puts each next to its mock in `build/screens/compare/`, and prints a summary (also in `summary.txt`) of the layout overflows and exceptions caught per screen, and on a player screen (`ScreenEntry.playerScreen`) every run of text drawn below the reading floor (16 px to act, 14 px captions, as drawn after any shrinking to fit) or set as an uppercase tracked micro-label (`test_screens/reading_floor.dart`). Text in the old theme's fonts is drawn in Figtree stand-ins (see above). `just screens 360` renders 360 wide into `build/screens/w360/`; `just screens 390 strict` exits non-zero on findings. A screen whose builder throws is reported as BUILD FAILED and always fails the run, with no PNG. It needs no backend and lives in `test_screens/`, outside `test/`, so `just test` never runs it (the same structural exclusion as `test_e2e/`); `test_screens/flutter_test_config.dart` reuses the test config, and `screen_gallery_test.dart` there proves the detector on every run. Every screen and state is one entry in `test_screens/screen_catalogue.dart`; `screen_fixtures.dart` reaches each state through the server's own payloads and events (no state the server cannot produce). A mock screen the app lacks, or cannot reach, is a `ScreenEntry.notBuilt` with the reason. The catalogue ends with the component sheet (`c-<page>-<ground>`, from `test/helpers/component_sheet.dart`): each mock rebuilt from the primitives next to its mock, and the state pages (buttons, players, gates, faces) on night, day and paper.

## Removing the old look

The old look (Firelit Gothic tokens, `lib/design_system/components/`) stays only while screens still use it. Every old-look file starts with `// OLD LOOK: delete when <screen> is rebuilt` and is a library marked `@Deprecated('OLD LOOK: ...')`, so the analyzer reports every import of it. `just analyze` (`tool/analyze_gate.sh`) lets those reports through only in the files listed in `tool/old_look_users.txt` (the users when it was marked) and fails on any other file's, so no new code takes up the old look; when a listed file stops using it, delete its line (the gate fails until you do). Delete an old-look file in the change that rebuilds the last screen named there.
