# Night protocol 2: the data layer (`features/game`)

The rebuilt screens read one model and one table; the old screens keep `GameNotifier` (protocol 1) until they go.
- **`/me/`**: `GameMe` (`features/game/domain/game_me.dart`), strict, with this phone's own `player_id` (never taken from the login). Its night is the design system's parsers run once on the same body (`ChoosePrompt.fromMe`, `NightSeat.seatsOf`, `NightReport.fromMe`): they ARE the night models, there is no second parser. Counts are `StageProgress`, the one parser for `/me/`'s `progress` and the `progress` event. Results: `GameOutcome` (`gameResultFromServer`, shared with protocol 1, plus `NightTimeline`). Lobby: `LobbyPlayer.token`, `LobbyState.table` (`TableSettings`: protocol, auto deck, chip, look); `MyTable`, `OnlineStats`, `RecentGame` (`lobby/domain/where_am_i.dart`).
- **Layering**: `features/game/domain` imports the night models from `design_system/night` and `design_system/faces` (they are the parsers, so the domain does not copy them); nothing in `design_system` imports a feature.
- **Screen**: `screenFor(TableView, me:, local:)` (`game/domain/screen_table.dart`) is the one server-state -> screen table (01 to 11; 05 is the board's place while `/me/` loads; a table naming no game of this player's is 02). `tableScreenProvider` (`game/presentation/table_screen.dart`) applies it: the game id comes from `/me/table/` (a new deal replaces the game), values held during a refetch are used (never loading or error while something is shown), a game that is gone is 01. The only non-server inputs are the `LocalSteps` in `localStepsProvider` (03 opened, "See who won"), each recorded with the table state it was taken in and void in any other, so a deal, play again or new game ends them. `screen_table_test.dart` maps every recorded protocol-2 `/me/` to the screen stated for it (`protocolTwoScreens` in `test/helpers/contract/sample_sets.dart`; a new sample must be added there), every where-am-I answer and lobby body, and checks every screen is reached.
- **State in**: `ProtocolTwoGameNotifier` (`protocolTwoGameProvider(gameId)`). `/me/` fetches go one at a time (a request meanwhile runs once after), so a reply never overtakes a newer one. One rule for every fetch a screen depends on: it is retried with backoff until it succeeds, or polled until its reason ends (`core/healing/healing.dart`, `HealTiming`): any failed `/me/` (the first, or the one after a taken choose) is fetched again; the results (`GameOutcome`) until they load; `myTableProvider` with `retryForever` (Riverpod's default gives up after about 40 s) and, at a waiting table or a finished game, a slow poll (`HealTiming.tablePoll`) for a lost deal or play-again event. Riverpod's own retry is off on the notifier (`noRetry`): it retries itself, and a rebuild would drop the taps in flight. Events (`GameEvent`) only ask for `/me/` (and `/me/table/`) again or update a value `/me/` holds in the same absolute form (progress, host via `player_id`, presence). Reconnect and app resume (`appResumesProvider`) fetch both; after a stage's deadline, by the server's clock (the last answer's `Date` plus the time since; the phone's clock only when no `Date` is readable, and then only to time a fetch), one fetch, then one every `HealTiming.poll` while the stage is unchanged; `/me/table/` and `/me/` are each fetched again when the other is ahead. A later good fetch clears `tableClosed`. The game sockets (`gameWebSocketProvider` and its stream and state) are autoDispose: a game no longer shown closes its socket.
- **Taps out**: one `Outbox` (`game/presentation/outbox.dart`), lanes choose, vote (pick and lock, in order), ready and ack: at most one request per lane in flight, later taps coalescing to the latest (queued), each item keyed to its stage (a choose: stage and turn) and holding its ORIGINAL request; an item of a stage or turn that ended is dropped, unsent ones included. What the screens show of this phone's taps is derived from it (`Outbox.on`), on the tap. Answers (`StageReply`, `StageAnswer` = `ChooseAnswer`): `taken` keeps the tap shown until a `/me/` fetched after it lands (after a taken choose every phone fetches once, so the Doppelganger's follow-up turn arms her board); an echo (`ready`, `target_player_id`) that differs fetches; `stale` (409) keeps it shown until the refetch lands; `refused` drops it; `notSent` keeps it with "Try again" (`retry(lane)`, `ProtocolTwoGame.unsent`), which fetches `/me/` first and resends the original only if it did not land (a choose: `prompt.chosen > request.chosen`); the results ack has no "Try again": it is sent again by itself with backoff, and whether it is done is read from `/me/`'s `night_results_seen`, so a restart does not resend it. After ANY taken choose every phone re-reads `/me/` and trusts its `chosen` and `chooses_left` (contract, third amendment). A choose is never sent twice for a turn. A tap the phone does not send is a `TapOutcome` of its own (`Declined`, `Queued`, `Landed`), never a made-up server answer; `TapOutcome.forBoard` gives the night board its `ChooseAnswer`.
- **Known and accepted**: a request whose answer was lost but which the server processes later can land after a newer tap of the same lane; closing that needs a per-phone sequence number on the server.
- **Requests**: `GameService.fetchMe`/`fetchMeTimed`, `send(StageRequest)` (`ChooseRequest.of(prompt, picks)`, which sends the prompt's `chosen` (required by the server: a lower one is a resend, answered alike and stored nowhere), `ReadyRequest`, `VoteRequest`, `AckRequest`; each echoes `stage`), `fetchOutcome`, and the host's `advanceStage`/`endTalk`/`revealVotesAt` (kept: the contract has them; no rebuilt screen calls them). `LobbyService.createTable` (`defaults: "v2"`, the only way a table is opened), `setDeckChip`, `setCustomDeck`, `setPace`, `patchSettings`, `setReady`, `fetchMyTable`, `fetchRecentGames`; `HomeService.fetchOnline` (no login); `myTableProvider`.

**Entry and shell (from the screens branch).** `GameEntry` picks the protocol-2 screens or the old ones through `gameProtocolProvider`, in every build (every table the app opens is protocol 2; the debug toolbar's "Rebuilt screens" switch, on by default, can still open a protocol-1 table until protocol 1 goes). `TableShell` hosts the rebuilt screens, at home (`/`, through `HomeGate`) and on the game route, and only `tableScreenProvider` decides which one shows: 01 to 03 are `features/lobby` (its README), a screen not built yet is a `NotBuiltScreen`; `StageSeconds` gives a screen the seconds left of its stage from the server's deadline (none when the stage has none).

Ordering in this layer was model-checked: `docs/dev/models/phone/`.
