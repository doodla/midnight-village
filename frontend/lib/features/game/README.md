# The game: the data layer and screens 04 to 11 (`features/game`)

There is one game flow: the screens read one model and one table.
- **`/me/`**: `GameMe` (`features/game/domain/game_me.dart`), strict, with this phone's own `player_id` (never taken from the login); it carries `stageStartedAt` (`stage_started_at`: when the timed stage began, null whenever the deadline is) and, in the vote, `voteTargets` (`vote_targets`: the ids this phone may vote for, in seat order), which no screen reads yet. Its night is the design system's parsers run once on the same body (`ChoosePrompt.fromMe`, `NightSeat.seatsOf`, `NightReport.fromMe`): they ARE the night models, there is no second parser. Counts are `StageProgress`, the one parser for `/me/`'s `progress` and the `progress` event. Results: `GameOutcome` (`gameResultFromServer` plus `NightTimeline`). A `/me/` without a `stage` key is a broken payload (`GameMe.fromJson` throws): a failed fetch, healed like any other, the taps in flight kept. Play again or Leave answered 404 is the table closing (01, "This table has closed."), as a fetch answered 404 is. Lobby: `LobbyPlayer.token`, `LobbyPlayer.connected`, `LobbyState.table` (`TableSettings`: auto deck, chip, look, lengths), `LobbyState.deckPreview` and `LobbyState.deal` (`DealReadiness`: the server's own "can be dealt now"; every table sends both); `MyTable`, `OnlineStats`, `RecentGame` (`lobby/domain/where_am_i.dart`).
- **Layering**: `features/game/domain` imports the night models from `design_system/night` and `design_system/faces` (they are the parsers, so the domain does not copy them); nothing in `design_system` imports a feature.
- **Screen**: `screenFor(TableView, me:, local:)` (`game/domain/screen_table.dart`) is the one server-state -> screen table (01 to 11; 05 is the board's place while `/me/` loads; a table naming no game of this player's is 02). `tableScreenProvider` (`game/presentation/table_screen.dart`) applies it: the game id comes from `/me/table/` (a new deal replaces the game), values held during a refetch are used (never loading or error while something is shown), a game that is gone is 01. Opening the app, it reads the seat this device last had (`LastSeat`, `features/lobby/presentation/last_seat.dart`, written from every `/me/table/` answer, read before the first frame by `restoreLocalSteps`) beside `/me/table/`: that game's `/me/` (or that waiting table's lobby) goes out at the same moment and is kept while `/me/table/` names the same seat, let go when it names another; a deal starts the dealt game's `/me/` from the deal's answer or `game_started` the same way (`AtTableScreen`). The seat is kept per account (`<user>:<seat>`) and cleared with it. Nothing here orders a fetch: the notifier's first fetch just starts sooner. Until `/me/table/` names its game (`LiveGameNotifier._named`), the notifier only reads: a 404 stops it quietly (no "This table has closed.", no retry), and nothing it hears asks for `/me/table/` again; once named it behaves as before. The only non-server inputs are the `LocalSteps` in `localStepsProvider` (03 opened, "See who won"), each recorded with the table state it was taken in and void in any other, so a deal, play again or new game ends them; "See who won" is also kept on the device (`mv.won.v1.<game>`, read before the first frame by `restoreLocalSteps`), so a restart at the results lands on 10 or 11 as this phone left it. `screen_table_test.dart` maps every recorded `/me/` to the screen stated for it (`meScreens` in `test/helpers/contract/sample_sets.dart`; a new sample must be added there), every where-am-I answer and lobby body, and checks every screen is reached.
- **Back**: one policy for the whole app (`core/router/back_policy.dart`), at the one page (`HomeGate`; the dev-only `/debug` page has its own, whose Back goes home): Android's back button and gesture (predictive back is opted in, `enableOnBackInvokedCallback`) and the browser's Back all arrive as the same `popRoute`. A sheet or dialog open on top closes first (it is a route; a sheet is never dragged, so the back swipe's own touch, which reaches the page until Android claims it, cannot close it first and leave Back to the screen: one gesture, one thing); else the last open `BackHandler` answers (03 back to 02, 02's leave question, My night put away on 08, 01's code field closed, "You're at another table." goes there as "Go there" does); else the screen's `BackRule`: `backRuleFor(AppScreen)` beside `screenFor` names one for every screen (01 leaves the app, 02 asks first through the table's own "Stay" / "Leave", never while a deal or a leave is on its way, 03 returns to 02, 04 to 11 do nothing: only Leave exits a game); `HomeGate` names the rule of its waits (the opening waits leave: the seat is the server's, reopening reads it back). A sheet or dialog never outlives its screen: `BackPolicy.place` changes with the screen, and every route above the page closes, its opener getting no answer (02's question when the deal comes, 08's role sheet when the vote opens). Only where Back leaves is Android told the app does not take it, so the back gesture previews leaving only on 01. On the web, `oneHistoryEntry` holds the browser's history to the engine's single entry over the page the app was opened from: every change of address replaces it (no game steps, nothing added by a reload or a link), and the browser's Back lands on the page under it, which the engine turns into `popRoute` and undoes. Where Back leaves, the web never uses the engine's exit (where there is no page before the app, a fresh tab, that exit takes the app's history down and Back stops working for good): the page never pops and the app steps two entries back (`leave_web.dart`), which does nothing in a fresh tab and leaves Back armed. A screen leaving under a change of screen answers nothing (`BackMute`, set by `SceneSwitcher`). `test/features/back_test.dart` presses Back on every screen the table can name (a new screen fails it until its rule is stated and pressed), on the waits and in flight; `test/core/router/back_policy_test.dart` holds the policy itself.
- **State in**: `LiveGameNotifier` (`liveGameProvider(gameId)`). `/me/` fetches go one at a time (a request meanwhile runs once after), so a reply never overtakes a newer one. One rule for every fetch a screen depends on: it is retried with backoff until it succeeds, or polled until its reason ends (`core/healing/healing.dart`, `HealTiming`): any failed `/me/` (the first, or the one after a taken choose) is fetched again; the results (`GameOutcome`) until they load (`outcomeFailing` while a try has failed); `myTableProvider` with `retryForever` (Riverpod's default gives up after about 40 s) and, at a waiting table or a finished game, a slow poll (`HealTiming.tablePoll`) for a lost deal or play-again event. Riverpod's own retry is off on the notifier (`noRetry`): it retries itself, and a rebuild would drop the taps in flight. Events (`GameEvent`) only ask for `/me/` (and `/me/table/`) again or update a value `/me/` holds in the same absolute form (progress, host via `player_id`, presence). Reconnect and app resume (`appResumesProvider`) fetch both; after a stage's deadline, by the server's clock (the last answer's `Date` plus the time since; the phone's clock only when no `Date` is readable, and then only to time a fetch), one fetch, then one every `HealTiming.poll` while the stage is unchanged; `/me/table/` and `/me/` are each fetched again when the other is ahead. A later good fetch clears `tableClosed`; a 404 also sets 01's banner ("This table has closed.", `JoinFlow.tableClosed`), where the phone lands. The game sockets (`gameWebSocketProvider` and its stream and state, `game/presentation/game_socket.dart`) are autoDispose: a game no longer shown closes its socket.
- **Taps out**: one `Outbox` (`game/presentation/outbox.dart`), lanes choose, vote (pick and lock, in order), ready and ack: at most one request per lane in flight, later taps coalescing to the latest (queued), each item keyed to its stage (a choose: stage and turn) and holding its ORIGINAL request; an item of a stage or turn that ended is dropped, unsent ones included. What the screens show of this phone's taps is derived from it (`Outbox.on`), on the tap. Answers (`StageReply`, `StageAnswer` = `ChooseAnswer`): `taken` keeps the tap shown until a `/me/` fetched after it lands (after a taken choose every phone fetches once, so the Doppelganger's follow-up turn arms her board); an echo (`ready`, `target_player_id`) that differs fetches; `stale` (409) keeps it shown until the refetch lands; `refused` drops it; `notSent` keeps it with "Try again" (`retry(lane)`, `LiveGame.unsent`), which fetches `/me/` first and resends the original only if it did not land (a choose: `prompt.chosen > request.chosen`); the results ack has no "Try again": it is sent again by itself with backoff, and whether it is done is read from `/me/`'s `night_results_seen`, so a restart does not resend it. After ANY taken choose every phone re-reads `/me/` and trusts its `chosen` and `chooses_left` (contract, section 5). A choose is never sent twice for a turn. A tap the phone does not send is a `TapOutcome` of its own (`Declined`, `Queued`, `Landed`), never a made-up server answer; `TapOutcome.forBoard` gives the night board its `ChooseAnswer`.
- **Known and accepted**: a request whose answer was lost but which the server processes later can land after a newer tap of the same lane; closing that needs a per-phone sequence number on the server.
- **Requests**: `GameService.fetchMe`/`fetchMeTimed`, `send(StageRequest)` (`ChooseRequest.of(prompt, picks)`, which sends the prompt's `chosen` (required by the server: a lower one is a resend, answered alike and stored nowhere), `ReadyRequest`, `VoteRequest`, `AckRequest`; each echoes `stage`), `fetchOutcome`, and the host's `advanceStage`/`endTalk`/`revealVotesAt` (kept: the contract has them; no rebuilt screen calls them). `LobbyService.createTable` (`defaults: "v2"`, the only way a table is opened), `setDeckChip`, `setCustomDeck`, `setPace`, `patchSettings`, `setReady`, `fetchMyTable`, `fetchRecentGames`; `HomeService.fetchOnline` (no login); `myTableProvider`.

**The shell.** `TableShell` hosts every screen, at home (`/`, through `HomeGate`) and on a game's link (`/game/<id>`), and only `tableScreenProvider` decides which one shows: 01 to 03 are `features/lobby` (its README); a game screen is built only from a `/me/` of its own phase (09 only from a voting `/me/`, and so on): while the table names a later phase than the `/me/` held, the screen shows its ground with nothing on it until its own `/me/` lands, never the earlier phase's values; `StageSeconds` gives a screen the seconds left of its stage from the server's deadline (none when the stage has none), and `StageShare.left` how much of it is left for the sun and the vote's bar, from `/me/`'s `stage_started_at` and `deadline` (the same on every phone and after a restart); null while the server does not send `stage_started_at`, and then nothing of a share is drawn. A change of screen is a crossfade (`Motion.settle`) except two, which are the scenes the whole table shares (`SceneSwitcher`, `design_system/README.md`): the dusk (`table` or `deck` to `yourCard` or `nightBoard`) and the dawn (`yourCard` or `nightBoard` to `talk`), chosen by `_sceneBetween` from the two `AppScreen`s; the dusk lowers the card's screen over the table's from above on a paper edge, the dawn sinks the night off the talk, whose own header rises into its window; nothing waits, and reduce motion cuts. While the game's `/me/` loads the destination shows its own frame with the one waiting body in it (`lib/features/game/presentation/shell/waits.dart`: `CardWait`, `TalkWait`, `VoteWait`, `GameWait`; `Waiting` from `design_system/primitives/waiting_sign.dart`) so a scene never lands on an empty ground and a wait is never a bare one; a failing first `/me/` says "One moment" with "Try again" in that frame (`LiveGameNotifier.refresh`). The results being read are one wait under one key (the `/me/` and the results answer into the same wait, so its sign does not blink). Over a screen that is shown, "One moment" appears (settling in over `Motion.settle`) whenever the fetches that keep it true fail, socket down or not; the seat and the screen stay. Vote to count stays a crossfade.

**08 Talk and 09 Vote** (`game/presentation/shell/talk_screen.dart`, `game/presentation/shell/vote_screen.dart`). Each is a wired screen (`TalkScreen`, `VoteScreen`: `/me/` with the outbox on it, the countdown, the notifier's taps) over a view that takes plain data and callbacks (`TalkView`, `VoteView`; the component sheet's 08 and 09 pages and so the cold-read pack draw these views). 08: the sun and the number with "The village wakes" beside it (`TimerBand.sun(title:)`); the body is given the room under the band (`ScreenFrame(fitsHeight:, minBodyHeight: TalkView.minBody)`: a phone too short for that scrolls the band and the body together). As the talk opens, a phone whose night told it something (`NightReport.tellsSomething`: a result other than "You slept." / "You did nothing.", or the copy) that `/me/` has not had acknowledged (`GameMe.hasUnseenResults`) shows My night OPEN once (`TalkView.resultOpen`: the `HeldFace` a hold shows, in the room, no hold); `TalkScreen` decides it on its first frame, sends the ack (`acknowledgeNightResults`) after that frame, and a tap puts it away (`onPutAway`); a restart after the ack opens nothing. Otherwise My night (`TeachingHold` over `PeekBox`, `NightReport.myNight`, the one `hold` cue; the first counted reveal sends the ack, which declines once done), large where the deck still fits under it with its portraits, else the mock's smaller box where that keeps them (`PeekBox.heightFor`), and the deck under it in the rest (`_DeckGrid`: each role once as a small portrait with its name, "3 Villagers" where there are several, in two columns at the acting size, then the caption size, then three, then the names alone; the first layout that holds every chip whole is used, a fading scroll only where none does; a tap or a hold opens the role sheet), plain pips and the count in full ink, "Ready to vote" quiet and never locked (open card or not), a toggle through the ready lane (`setReady(!ready)`). No names: the vote lists them. 09: "Who dies today?" beside the number in the band (`TimerBand.bar(title:)`); the rows are `VoteView.votable(me)`: `/me/`'s `vote_targets` when sent, else everyone but this phone (drop that fallback once the server sends it); sized to the room (`VoteRows`: tall rows, compact rows, then a fading scroll, measuring each name at the text size, a practice player's with its "Practice" tag (`GameMe.practiceIds`, from `players[].practice`); each row keeps the lift's room out of the gap so a lifted row leaves the gaps even); a tap picks (`pickVote`), "Lock in {name}" locks (`lockVote`, after the picks before it on the vote lane); locked, the pick stays lifted and outlined and the others dim; `my_vote` from `/me/` restores picked or locked; the `vote_lock` cue is learned when the server has the lock (the lane's lock confirming, or `/me/` locked), not on the tap, since a lock can wait behind a pick. Both count this phone's own ready or lock at once (`GameMe.withReady`, `withVote` move `progress` against the flag of the same `/me/`); a `progress` event that arrives while that tap is unconfirmed fetches `/me/` instead of being applied, so the count and the flag always come from one answer. Both show "Not sent." with "Try again" only for their own lane's unsent tap.

**10 and 11 (`lib/features/game/presentation/shell/count_screen.dart`, `lib/features/game/presentation/shell/results_screen.dart`).** Drawn from the results body alone, through `lib/features/game/domain/outcome_view.dart`: `TheCount` (the votes grouped by whom they named, most first; who did not vote; who died by the vote and by the Hunter, from `is_eliminated` and `elimination_reason`), `EndSeat` (each player's dealt and final card, a Doppelganger's copied role from the timeline's `copy` step, team and outcome as the server says), `Winners` (`winning_teams`), `nightLinesOf` (the timeline as one line per step, with the cards it showed or moved; werewolf cards by the server's `werewolf`). Nothing applies a rule; red is the server's `werewolf` flag on a card, everywhere (`EndSeat.werewolfNow`, `NightLine.werewolf`, `werewolfPathsOf`), and a death with no reason fails loudly. 10: the dead card first (the player's name and "Now" from the start, "Now" and "Dealt" at the acting size in full ink; as it turns, the final card large with its team, "Dealt" and an arrow before it when it moved; several dead: smaller cards, "Dealt"/"Now" said once), then the rows, outlined only for the players the vote killed ("You" on this phone's own row and dead card: `CountView.viewerId`), and "{name}, {hunter}'s pick, dies too." for the Hunter's; the rows land and the cards turn, but "See who won" works at once and any tap finishes the motion. 11: the winners' band, "You won."/"You lost.", every player's card (dealt, arrow, final) with "Won"/"Died", one compact line each, the center, then the night open (the red line: where each Werewolf card went; then a line per step on a spine red where a werewolf card was touched; a tap on the red line folds it; a big table's continues under the fade); host "Play again" and "Edit deck" (play again, then 03), stacked when a label would not fit on one line; guest "{host} deals next." (when the host is at the table) as the message, with "Leave" a quiet word beside it (`TextAction`), never a button; the viewer's own row says "You" (`YouTag`); the night scrolls fully clear of the pinned line (its last step whole above it, at five and ten, 390 x 844 and 360 x 640), under a fade never taller than what is still below; the steps, their numbers and the center in full ink; a request is a `Pending` (only the tapped button shows busy, until 02 is up; "Not sent." with "Try again" when no answer came, the server's reason with no button when it refused: "Can't deal yet.", "Can't leave now."). Both wait with the waiting body in the screen's header (`EndWaiting`) until the results load. `CountView` and `ResultsView` take plain data, so the component sheet draws them too.
