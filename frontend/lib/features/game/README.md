# The game: the data layer and screens 04 to 10 (`features/game`)

There is one game flow: the screens read one model and one table.
- **`/me/`**: `GameMe` (`features/game/domain/game_me.dart`), strict, with this phone's own `player_id` (never taken from the login); it carries `stageStartedAt` (`stage_started_at`: when the timed stage began, null whenever the deadline is) and, in the vote, `voteTargets` (`vote_targets`: the ids this phone may vote for, in seat order), which no screen reads yet. Its night is the design system's parsers run once on the same body (`ChoosePrompt.fromMe`, `NightSeat.seatsOf`, `NightReport.fromMe`): they ARE the night models, there is no second parser. Counts are `StageProgress`, the one parser for `/me/`'s `progress` and the `progress` event. Results: `GameOutcome` (`gameResultFromServer` plus `NightTimeline`). A `/me/` without a `stage` key is a broken payload (`GameMe.fromJson` throws): a failed fetch, healed like any other, the taps in flight kept. Play again or Leave answered 404 is the table closing (01, "This table has closed."), as a fetch answered 404 is. Lobby: `LobbyPlayer.token`, `LobbyPlayer.connected`, `LobbyState.table` (`TableSettings`: auto deck, chip, look, lengths), `LobbyState.deckPreview` and `LobbyState.deal` (`DealReadiness`: the server's own "can be dealt now"; every table sends both); `MyTable`, `OnlineStats`, `RecentGame` (`lobby/domain/where_am_i.dart`).
- **Layering**: `features/game/domain` imports the night models from `design_system/night` and `design_system/faces` (they are the parsers, so the domain does not copy them); nothing in `design_system` imports a feature.
- **Screen**: `screenFor(TableView, me:, local:)` (`game/domain/screen_table.dart`) is the one server-state -> screen table (01 to 10; 05 is the board's place while `/me/` loads; a table naming no game of this player's is 02). `tableScreenProvider` (`game/presentation/table_screen.dart`) applies it: the game id comes from `/me/table/` (a new deal replaces the game), values held during a refetch are used (never loading or error while something is shown), a game that is gone is 01. Opening the app, it reads the seat this device last had (`LastSeat`, `features/lobby/presentation/last_seat.dart`, written from every `/me/table/` answer, read before the first frame by `restoreLocalSteps`) beside `/me/table/`: that game's `/me/` (or that waiting table's lobby) goes out at the same moment and is kept while `/me/table/` names the same seat, let go when it names another; a deal starts the dealt game's `/me/` from the deal's answer or `game_started` the same way (`AtTableScreen`). The seat is kept per account (`<user>:<seat>`) and cleared with it. An answer or an event that says where this player sits is `/me/table/`'s next value, not asked again (`SeatSeed`, `seatFromServer` in `lobby/presentation/where_am_i_provider.dart`; `MyTable.seatedAt`, `MyTable.backToWaiting`): a table started or joined, a deal and `game_started` (the night of the new game), play again and `play_again` at the end board (the lobby, waiting, this game still its newest, as `/me/table/` says it; `LiveGameNotifier._seatBackAtTable`: only from the end board of this game, and not while this phone's own play again is out, whose answer seats it with the lobby). A read still out when a seat is put is dropped (the newest read alone counts, and a dropped read arms no poll), so an older answer never moves the screen back (`docs/dev/models/phone/seat/`). Nothing here orders a fetch: the notifier's first fetch just starts sooner. Until `/me/table/` names its game (`LiveGameNotifier._named`), the notifier only reads: a 404 stops it quietly (no "This table has closed.", no retry), and nothing it hears asks for `/me/table/` again; once named it behaves as before. The only non-server inputs are the `LocalSteps` in `localStepsProvider` (03 opened, "See who won"), each recorded with the table state it was taken in and void in any other, so a deal, play again or new game ends them; "See who won" is also kept on the device (`mv.won.v1.<game>`, read before the first frame by `restoreLocalSteps`), so a restart at the results lands on 10 or 11 as this phone left it. `screen_table_test.dart` maps every recorded `/me/` to the screen stated for it (`meScreens` in `test/helpers/contract/sample_sets.dart` is derived from each sample's own phase and stage, so a new sample needs no line; one whose stage names no screen fails there), every where-am-I answer and lobby body, and checks every screen is reached.
- **Back**: one policy for the whole app (`core/router/back_policy.dart`), at the one page (`HomeGate`; the dev-only `/debug` page has its own, whose Back goes home): Android's back button and gesture (predictive back is opted in, `enableOnBackInvokedCallback`) and the browser's Back all arrive as the same `popRoute`. A sheet or dialog open on top closes first (it is a route; a sheet is never dragged, so the back swipe's own touch, which reaches the page until Android claims it, cannot close it first and leave Back to the screen: one gesture, one thing); else the last open `BackHandler` answers (03 back to 02, 02's leave question, My night put away on 08, 01's code field closed, "You're at another table." goes there as "Go there" does); else the screen's `BackRule`: `backRuleFor(AppScreen)` beside `screenFor` names one for every screen (01 leaves the app, 02 asks first through the table's own "Stay" / "Leave", never while a deal or a leave is on its way, 03 returns to 02, 04 to 11 do nothing: only Leave exits a game); `HomeGate` names the rule of its waits (the opening waits leave: the seat is the server's, reopening reads it back). A sheet or dialog never outlives its screen: `BackPolicy.place` changes with the screen, and every route above the page closes, its opener getting no answer (02's question when the deal comes, 08's role sheet when the vote opens). Only where Back leaves is Android told the app does not take it, so the back gesture previews leaving only on 01. On the web, `oneHistoryEntry` holds the browser's history to the engine's single entry over the page the app was opened from: every change of address replaces it (no game steps, nothing added by a reload or a link), and the browser's Back lands on the page under it, which the engine turns into `popRoute` and undoes. Where Back leaves, the web never uses the engine's exit (where there is no page before the app, a fresh tab, that exit takes the app's history down and Back stops working for good): the page never pops and the app steps two entries back (`leave_web.dart`), which does nothing in a fresh tab and leaves Back armed. A screen leaving under a change of screen answers nothing (`BackMute`, set by `SceneSwitcher`). `test/features/back_test.dart` presses Back on every screen the table can name (a new screen fails it until its rule is stated and pressed), on the waits and in flight; `test/core/router/back_policy_test.dart` holds the policy itself.
- **State in**: `LiveGameNotifier` (`liveGameProvider(gameId)`). `/me/` fetches go one at a time (a request meanwhile runs once after), so a reply never overtakes a newer one. One rule for every fetch a screen depends on: it is retried with backoff until it succeeds, or polled until its reason ends (`core/healing/healing.dart`, `HealTiming`): any failed `/me/` (the first, or the one after a taken choose) is fetched again; the results (`GameOutcome`) until they load (`outcomeFailing` while a try has failed); `myTableProvider` with `retryForever` (Riverpod's default gives up after about 40 s) and, at a waiting table or a finished game, a slow poll (`HealTiming.tablePoll`) for a lost deal or play-again event. Riverpod's own retry is off on the notifier (`noRetry`): it retries itself, and a rebuild would drop the taps in flight. Events (`GameEvent`) only ask for `/me/` (and `/me/table/`) again or update a value `/me/` holds in the same absolute form (progress, host via `player_id`, presence). Reconnect and app resume (`appResumesProvider`) fetch both; after a stage's deadline, by the server's clock (the last answer's `Date` plus the time since; the phone's clock only when no `Date` is readable, and then only to time a fetch), one fetch, then one every `HealTiming.poll` while the stage is unchanged; `/me/table/` and `/me/` are each fetched again when the other is ahead. A later good fetch clears `tableClosed`; a 404 also sets 01's banner ("This table has closed.", `JoinFlow.tableClosed`), where the phone lands. The game sockets (`gameWebSocketProvider` and its stream and state, `game/presentation/game_socket.dart`) are autoDispose: a game no longer shown closes its socket.
- **Taps out**: one `Outbox` (`game/presentation/outbox.dart`), lanes choose, vote (pick and lock, in order), ready and ack: at most one request per lane in flight, later taps coalescing to the latest (queued), each item keyed to its stage (a choose: stage and turn) and holding its ORIGINAL request; an item of a stage or turn that ended is dropped, unsent ones included. What the screens show of this phone's taps is derived from it (`Outbox.on`), on the tap. Answers (`StageReply`, `StageAnswer` = `ChooseAnswer`): `taken` keeps the tap shown until a `/me/` fetched after it lands (after a taken choose every phone fetches once, so the Doppelganger's follow-up turn arms her board); an echo (`ready`, `target_player_id`) that differs fetches; `stale` (409) keeps it shown until the refetch lands; `refused` drops it; `notSent` keeps it with "Try again" (`retry(lane)`, `LiveGame.unsent`), which fetches `/me/` first and resends the original only if it did not land (a choose: `prompt.chosen > request.chosen`); the results ack has no "Try again": it is sent again by itself with backoff, and whether it is done is read from `/me/`'s `night_results_seen`, so a restart does not resend it. After ANY taken choose every phone re-reads `/me/` and trusts its `chosen` and `chooses_left` (contract, section 5). A choose is never sent twice for a turn. A tap the phone does not send is a `TapOutcome` of its own (`Declined`, `Queued`, `Landed`), never a made-up server answer; `TapOutcome.forBoard` gives the night board its `ChooseAnswer`.
- **A newer build**: `mayReloadNow` (`game/domain/reload_rule.dart`) is the one place that says when the open app may reload itself for a newer build (`core/update/new_build.dart`, `new_build_provider.dart`; `docs/dev/deploy-vercel.md`): never with a `playerRequest` out, an outbox tap queued, in flight or unsent (`Outbox.hasTapsOnTheWay`), a host's change on its way, a name or code typed on 01 (`JoinDraft`, also kept across a reload in the tab's `sessionStorage`, `TabStorage`), text in the focused field or the camera scanner open; at once on 01, 02, 03 and 11 and on "You're at another table."; in a running game (04, the night board, 08, 09, 10) NEVER on a phase change or on the timer, only when the tab comes back after being hidden for more than 5 s (`NewBuild.awayFor`), else when the game ends (11) or the table shows. The service worker is asked to update and to take over first (`renewWorker`, 10 s bound; nothing is unregistered or deleted; a failure leaves the app running and the next look tries again). The loop guard (the build reloaded for) is per tab. `HomeGate` reports what is shown (`NewBuild.seen`).
- **The end board** (`game/presentation/end/`): the results phase's one screen (`AppScreen.end`). `EndScreen` (`game/presentation/shell/end_screen.dart`) wires it: the wait until the results load (`EndWaiting`), host Play again / Edit deck and guest Leave as one `Pending` each (busy on the control tapped, `PaperScrap.busy`, the mark in the scrap's own end room, its words readable; the failure and "Try again" on one line over the foot), "What happened"'s cue as the learned `Cue.endStep`, and the reveal latched by `EndRevealLatch` (`endRevealLatchProvider`): the shell marks a game in play while it shows its night, talk or vote, and a board plays its reveal only the first time it is shown for that game in this run, on a phone that saw it played; a remount, refetch, turned phone or late arrival is settled (`end_board_shell_test.dart`). `EndBoardView` draws the settled board from the plan `planEndBoard` makes (planned once per room, text size, payload, viewer and host, the banner fitted once per payload and viewer). With `reveal: true` it plays the reveal once (`docs/specs/frontend/end-board.md`, section 8): `revealOf(plan)` (`game/domain/end_reveal.dart`) is the timeline, named beats with start and length from the `Motion` tokens (hold; for each death in turn its lift and turn, stamp with a knock, drop and ribbon, the banner unrolling from its furl with the first; or, nobody hanged, the winners rising; the rows' turns, the Hunter's pick, grow, pool, tags); one `AnimationController` is its clock (`EndRevealDriver`, in `EndRevealScope`), and every moving piece is a `RevealPaint` that listens to it and paints its child again moved, faded or clipped (its `applyPaintTransform` tells hit tests and the reading floor's guard where and how large it really is), so a frame builds and lays out nothing and the still paper is never painted again (`end_reveal_test.dart` counts it). Cards never change places: face down in their own slots from frame one, every back one portrait size, the board already where it opens; each dead card lifted big by a twin over the board (its art filling it) and handed back to the slot. Nothing is drawn smaller than it is (a back grows into its face edge on; a test runs the reading floor on every frame). A touch anywhere settles it in one frame and still reaches the control under it (the board keeps its layers settled); reduce motion or a screen reader gets the settled board faded in; a knock as each stamp lands (`Haptics.thud`; `Haptics.light` once when nobody is hanged), and one on a skip if none had come; without `reveal` (opened late) nothing moves or vibrates. With no driver every piece is drawn exactly as the static board is (a test compares the pixels).
  - **What happened** replays the night on the board itself, calm, one thing at a time. `endStoryOf(outcome)` (`game/domain/end_story.dart`, pure) turns the results' `night_timeline` into the board's steps: the faces as dealt, then one step per timeline step that did something (a `skip` is left out; roles in the middle and Villagers never have one), each with its kind (team, copy, look, take, swap), who acted, its threads (from who looked to what they saw, from who took to where they took it, between the two swapped, along a team; the Minion to each Werewolf), red only for the Werewolf team's own acts, its line and every card's face after it, by `cardFace`, the one rule the settled board uses too: a card shows its own role wherever it moves; the Doppelganger card, once it has copied and while a player holds it, shows the copied role and says "Doppelganger" (its holder plays the copied role, as the server scores it); in the middle it is a Doppelganger card. `end_story_test.dart` checks it on every recorded results body: at the deal and after every step, every seat's and middle card's face is the card the recording's `positions_after` puts there (red against the recording's own role words). The lines come from one function, `StoryCopy.line` (`design_system/copy/end_copy.dart`, a part of `copy.dart`; every form in `story_copy_test.dart`): the role first, then who, then what came of it ("Seer Ana sees Cleo: Werewolf.", "Doppelganger Ana copies Ben: now a Seer."), never a bare "Left"/"Right"/"Middle". `planEndBoard` makes each card, and the foot each middle card, as wide as every role it shows through the night, so nothing moves when the faces change. `EndNight` (`presentation/end/end_night.dart`, in `EndNightScope`) is the step shown (0 is the deal) and the clock of its motion: the scrap opens it at the deal (the reveal settles first) and becomes "The result"; a tap on the board or a swipe left plays the next step or finishes the one playing, a swipe right shows the one before, a tap after the last is back at the result; nothing advances by itself and nothing vibrates; reduce motion or a screen reader cuts every change. The banner says the step's line (a live region and a screen reader's way on) and keeps the room the tallest of the result and the night's lines needs, so the board never moves. The settled board is hidden as it is (`NightHides`) and comes back pixel for pixel, scrolled where it stood; the night is a layer over it (`NightBoard`, `end_night_board.dart`): the moon up behind the roofs (`NightMoon`, in the dawn sky's slot) under a veil (`NightSky`), the lantern out, each card turning to the deal and then to each step's faces where it lies, and only the step's own thread (no numbers, nothing left by earlier steps); each link is a `CardLink` tied between the cards as they lie (`end_night_links.dart`, `nightStepOf`), drawn thicker than a twine so it reads at arm's length (the skin's `PaperParts.linkWidth`, `linkHead`, `linkDot`, `linkDash`, `linkGap`): a middle card the step is about is lifted onto the board beside the one who acted (`nightLiftedOf`, `nightMiddleAt`), clear of every player's name (`nightNameOf`: the letters' room, turned with the card): side by side, else two fanned, else none, and then the cards stay in the foot raised and the thread runs down to them over the lip (`NightFootLinks`, `end_night_foot.dart`; the foot and the board agree through `EndNight.laidOut`, the plan the board was last laid out with), and a card no clean link can reach is lifted beside the other end; `test/helpers/end_links.dart` is the links' rule, in the night sweep and the `12-end-night-*` pages' sweep plan. On a board that scrolls, `nightViewOf` (`domain/end_night_view.dart`, pure) centres the step's cards (the deal: the top, with "you"), and where they cannot be in the window together lifts the others to the window's edge for the step (clear of the other players' names where it can); everything the night lays out is read from the plan as it is now, so when the plan is made again (a turned phone, split screen, a new text size) at any step, even mid-motion, the board is brought where that plan has the step (`EndBoardWindow`'s `_aim`, keyed on the step and the scroll it brings, never on the plan object), and back at the result it stands where it stood by day; `end_night_sweep_test.dart` fails when any card of the step shown is clipped, covered or off screen (every recorded night, ten players and a night where nobody acted, four phones with the owner's 412 x 915, three text sizes; the states it does not hold yet are its `_notYetSwept`, one line each, a list that only shrinks). The first time, "Go on" on the board's lower edge until the first tap (`stepTaught`, `onStepTaught`; `Cue.endStep`). `end_night_test.dart`: the deal in place, the lines in the banner, the tap, the swipe, the way back, no vibration, the still paper not painted during a step, a refetch of the same results changes nothing (`GameOutcome` is equal by its body), Play again and Edit deck take a real touch at night, the cue, the moon. Pages: `test_screens/end_night_pages.dart` (`12-end-night-*`); film: `just end-night-frames`.
- **Known and accepted**: a request whose answer was lost but which the server processes later can land after a newer tap of the same lane; closing that needs a per-phone sequence number on the server.
- **Requests**: `GameService.fetchMe`/`fetchMeTimed`, `send(StageRequest)` (`ChooseRequest.of(prompt, picks)`, which sends the prompt's `chosen` (required by the server: a lower one is a resend, answered alike and stored nowhere), `ReadyRequest`, `VoteRequest`, `AckRequest`; each echoes `stage`), `fetchOutcome`, and the host's `advanceStage`/`endTalk`/`revealVotesAt` (kept: the contract has them; no rebuilt screen calls them). `LobbyService.createTable` (`defaults: "v2"`, the only way a table is opened), `setDeckChip`, `setCustomDeck`, `setPace`, `patchSettings`, `setReady`, `fetchMyTable`, `fetchRecentGames`; `HomeService.fetchOnline` (no login); `myTableProvider`.

**The shell.** `TableShell` hosts every screen, at home (`/`, through `HomeGate`) and on a game's link (`/game/<id>`), and only `tableScreenProvider` decides which one shows: 01 to 03 are `features/lobby` (its README); a game screen is built only from a `/me/` of its own phase (09 only from a voting `/me/`, and so on): while the table names a later phase than the `/me/` held, the screen shows its ground with nothing on it until its own `/me/` lands, never the earlier phase's values; `StageSeconds` gives a screen the seconds left of its stage from the server's deadline (none when the stage has none), and `StageShare.left` how much of it is left for the sun and the vote's bar, from `/me/`'s `stage_started_at` and `deadline` (the same on every phone and after a restart); null while the server does not send `stage_started_at`, and then nothing of a share is drawn. A change of screen is a crossfade (`Motion.settle`) except two, which are the scenes the whole table shares (`SceneSwitcher`, `design_system/README.md`): the dusk (`table` or `deck` to `yourCard` or `nightBoard`) and the dawn (`yourCard` or `nightBoard` to `talk`), chosen by `_sceneBetween` from the two `AppScreen`s; the dusk lowers the card's screen over the table's from above on a paper edge, the dawn sinks the night off the talk, whose own header rises into its window; nothing waits, and reduce motion cuts. While the game's `/me/` loads the destination shows its own frame with the one waiting body in it (`lib/features/game/presentation/shell/waits.dart`: `CardWait`, `TalkWait`, `VoteWait`, `GameWait`; `Waiting` from `design_system/primitives/waiting_sign.dart`) so a scene never lands on an empty ground and a wait is never a bare one; a failing first `/me/` says "One moment" with "Try again" in that frame (`LiveGameNotifier.refresh`). The results being read are one wait under one key (the `/me/` and the results answer into the same wait, so its sign does not blink). Over a screen that is shown, "One moment" appears (settling in over `Motion.settle`) whenever the fetches that keep it true fail, socket down or not; the seat and the screen stay. Vote to count stays a crossfade.
